Companies don’t share the same period beginning dates. Review the fiscal calendars before purging — the cutoff may not line up the same way across every company.
This is permanent. Once a new start date takes effect on the next refresh, all data before it is purged on the server — you can’t go back without a full reset. Strongly recommended: have IT back up the database first. There is no other recovery.

Why purge? Large databases cause real problems

  • Performance — queries and refreshes slow down as history piles up.
  • Disk space — the database file can grow until it fills the drive.
  • tempdb — big operations can exhaust tempdb and crash the server.
  • Autogrowth — frequent file growth fragments the database and stalls writes.
